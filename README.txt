СМЕНА — УЧЁТ РАБОЧЕГО ВРЕМЕНИ НА PYTHON + FASTAPI

БЫСТРЫЙ ЗАПУСК
1. Установите Python 3.10 или новее с python.org. При установке включите Add Python to PATH.
2. Дважды щёлкните «Запустить.cmd». Скрипт создаст .venv и установит зависимости.
   При первой установке нужен интернет. Node.js для Python-версии не требуется.
3. Откройте http://127.0.0.1:8000
4. При первом входе задайте пароль администратора (10–128 символов).
   Администратор: Адиль Кубентаев. Логин: Adilium.
5. Создайте сотрудников в разделе «Сотрудники», назначьте логины, пароли и права.
Сервер должен оставаться запущенным. Остановка: Ctrl+C.
Открытие HTML через file:// не запускает сервер и SQL-базу.

РУЧНОЙ ЗАПУСК (WINDOWS, POWERSHELL)
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run.py
Активация окружения не обязательна. Все команды выполняются из папки smena.
Для разработки с перезапуском при изменении кода: python run.py --reload
На Linux/macOS: python3 -m venv .venv, затем используйте .venv/bin/python.

ТЕХНОЛОГИИ И API
Python + FastAPI — сервер, Uvicorn — запуск HTTP-приложения.
SQLAlchemy — ORM и транзакции; SQLite — SQL-база в файле.
Pydantic — схемы запросов и ответов, проверка типов и допустимых значений.
Jinja2 — формирование всех разделов на сервере из данных SQL-базы.
HTML содержит строки таблиц, карточки и показатели уже до выполнения JavaScript.
CSS отвечает за оформление, JavaScript — за таймер, диалоги и отправку изменений.
Интерактивная документация: http://127.0.0.1:8000/docs
ReDoc: http://127.0.0.1:8000/redoc
Схема OpenAPI: http://127.0.0.1:8000/openapi.json
Для кнопки Authorize в Swagger используется OAuth2 Password Flow: POST /api/token.
В этом запросе логин и пароль отправляются как форма; ответ содержит access_token.
Для дальнейших API-запросов: Authorization: Bearer <access_token>.
Веб-интерфейс использует POST /api/login (JSON) и защищённую cookie.
Ошибки валидации запроса возвращаются со статусом 422; нарушение прав — 403.
Pydantic проверяет тело запроса, UUID в адресе, даты, статусы и параметры страницы.

СТРАНИЦЫ, ПОИСК И ПАГИНАЦИЯ
Основные разделы открываются обычными ссылками: /?view=overview, history, employees,
calendar, requests, reports, timesheet, audit. Нужное значение задаётся после view=.
Фильтры отправляются GET-формами, поэтому адрес можно сохранить и открыть повторно.
История смен, сотрудники, заявки и журнал разбиты на страницы с подсчётом записей.
Выборка выполняется SQL-запросами LIMIT/OFFSET, а не обрезанием списка в браузере.
Пример: /?view=history&page=2&pageSize=20&status=finished
Поиск сотрудников учитывает кириллицу; можно включить архивные профили.
При изменении или удалении записи сохраняются текущие фильтры и номер страницы.
Если последняя страница опустела, сервер показывает ближайшую существующую страницу.
API списков: /api/shifts, /api/users, /api/absence-requests и /api/audit.
Параметры page и pageSize управляют страницей; ответ содержит pagination с общим числом записей.
Для совместимости старые запросы пользователей, заявок и журнала без page сохраняют прежний формат.

БАЗА ДАННЫХ
Локальная SQLite-база: data/smena.sqlite. Создаётся при первом запуске.
База не находится в публичной папке, не скачивается через сайт и не входит в архив исходников.
Данные сохраняются после перезагрузки браузера и перезапуска сервера.
Перед первым открытием существующей SQLite-базы Python-версия сохраняет резервную копию.
Имя копии: data/smena.sqlite.before-fastapi.bak. Копия создаётся через SQLite Backup API.
Идентификаторы сотрудников, смены, перерывы и журнал действий сохраняются.
Для последующих резервных копий остановите сервер и скопируйте папку data целиком.
Модели Python: backend/models.py. Исходная совместимая SQL-схема: db/schema.sql.
Файл базы можно открыть в SQLite/DB Browser for SQLite после остановки приложения.
Не запускайте старый и новый серверы одновременно с одной базой во время переноса.
Опубликованная ранее версия использует D1 (SQLite); локальная и облачная базы независимы.
Данные из D1 не переносятся в локальную SQLite автоматически.

ТАБЛИЦЫ
users — профили сотрудников, логины, хеши паролей, роли и состояние аккаунта.
user_permissions — индивидуально назначенные права сотрудников.
schedules — рабочие дни недели, время начала/окончания и план перерывов.
shifts — фактические смены, заметки и версия записи для защиты от одновременной правки.
breaks — перерывы внутри смен.
absences — отмеченные администратором отпуска, выходные и другие отсутствия.
absence_requests — заявки сотрудников на отпуск и отгул, их статусы и решения администратора.
sessions — отзываемые серверные сессии JWT с ограниченным сроком действия.
login_attempts — ограничение частых попыток подбора пароля.
audit_log — журнал действий администратора и изменений записей.
Внешние ключи связывают сотрудника, его смены и перерывы.

ПРАВА
Администратор имеет доступ ко всем сотрудникам, сменам, графикам и отчётам.
Он создаёт и редактирует профили, сбрасывает пароли, блокирует вход,
архивирует и восстанавливает сотрудников, назначает права, меняет смены и перерывы.
Архивирование сохраняет историю; отдельные смены можно удалить с подтверждением.
Защищённого главного администратора нельзя заблокировать или удалить из интерфейса.
Каждый сотрудник может исправлять только свои существующие смены.
Для исправления обязательно указать причину; журнал сохраняет старые и новые значения.
Отдельно администратор назначает права:
- учёт своей смены и перерывов;
- изменение своего профиля;
- ручное добавление и удаление своих смен;
- просмотр своих отчётов;
- экспорт своих отчётов.
Сотрудник не может получить чужую историю или изменить права запросом к серверу.

КАЛЕНДАРЬ, КОМАНДА И ТАБЕЛЬ
Календарь показывает план, фактические часы, перерывы, опоздания и переработку.
Выберите день для просмотра его смен и перехода к исправлению времени.
Администратор отмечает отсутствия диапазоном дат и видит текущие статусы команды.
Сотрудник видит только собственный календарь и свои отсутствия.
Отмеченное отсутствие снимает план на этот день и не считается пропуском.
Фактически отработанные часы при этом сохраняются.
Табель за месяц доступен сотруднику с правом просмотра отчётов;
администратору доступен общий табель. Кнопка печати открывает системный диалог:
для PDF выберите в нём «Сохранить как PDF».

ЗАЯВКИ НА ОТПУСК И ОТГУЛ
Сотрудник открывает «Заявки» или кнопку запроса в календаре, выбирает вид отсутствия,
первый и последний день включительно и при необходимости оставляет комментарий.
До решения администратора заявка не меняет календарь или план рабочего времени.
Сотрудник видит только свои заявки и может отменить ещё не рассмотренную заявку.
Администратор видит общую очередь и может одобрить или отклонить заявку.
При отклонении требуется причина; сотрудник увидит её рядом со статусом заявки.
Одобрение автоматически добавляет отсутствие в календарь и месячный табель.
Пересекающиеся отсутствия и повторное одобрение не создают дубликатов.
Подача, отмена и решение сохраняются в журнале действий.
Если администратор позднее удалит отсутствие из календаря, история решения по заявке сохранится.

ПРАВИЛА РАСЧЁТА
Часовой пояс: Казахстан, UTC+5. План строится по текущему графику сотрудника;
исторические версии графиков в этой версии не ведутся.
Ночная смена целиком относится к дате её начала, включая перерывы после полуночи.
Опоздание — время от планового начала до первой фактической смены этого дня.
Переработка — положительная разница между фактическими часами без перерывов и планом.
Без фактической смены опоздание не начисляется; пропуск определяется после конца плана.
Будущие дни и дни до создания аккаунта не считаются пропусками.
Существующие отчёты по диапазону дат считают интервалы календарных суток;
для ночных смен их распределение по дням может отличаться от табеля по дате начала.

БЕЗОПАСНОСТЬ
Новые пароли хранятся как bcrypt_sha256-хеши с индивидуальной случайной солью (Passlib).
bcrypt_sha256 поддерживает пароли до 128 символов без усечения на 72 байтах bcrypt.
Старые scrypt-хеши проверяются при входе и заменяются новым хешем после успешной проверки.
Повторно задавать пароль существующему администратору для переноса не требуется.
JWT подписан серверным ключом; сессия дополнительно проверяется по SQL-базе.
Веб-вход использует HttpOnly-cookie; токен не хранится в localStorage.
Изменения через cookie защищены проверкой Origin и CSRF-токеном.
Swagger и другие API-клиенты используют Bearer-токен; cookie для этого не требуется.
SQLAlchemy передаёт значения отдельно от SQL-запросов.
Блокировка, архивирование и смена пароля отзывают существующие сессии.
Секреты, пароли и cookie не записываются в журнал действий.
По умолчанию сервер доступен только на этом компьютере (127.0.0.1).
Опубликованная страница входа доступна всем; рабочие данные требуют аккаунта и проверяются сервером.
Для первого запуска Python-сервера по внешнему адресу нужен SMENA_SETUP_TOKEN.
Ссылка настройки: https://ваш-домен/#setup=<SMENA_SETUP_TOKEN>.
Используйте случайное значение из латинских букв, цифр, дефисов и подчёркиваний.
Ключ хранится только в окружении сервера, не в исходниках и не в общедоступной ссылке.
После создания первого администратора повторная настройка запрещена даже с этим ключом.

НАСТРОЙКА ОКРУЖЕНИЯ
SMENA_DATABASE_URL — SQLAlchemy URL базы. По умолчанию SQLite: data/smena.sqlite.
  В этом выпуске поддерживается SQLite; адрес PostgreSQL пока не поддерживается.
SMENA_JWT_SECRET — постоянный случайный секрет подписи JWT, не менее 32 байт.
  При локальном запуске без этой переменной сервер создаёт ключ в data/jwt_secret.
  Папку data нужно сохранять между перезапусками и не размещать в public.
SMENA_SETUP_TOKEN — ключ первоначальной настройки для доступа по внешнему адресу.
  Рекомендуется случайная строка не короче 43 символов, например результат secrets.token_urlsafe(32).
SMENA_SECURE_COOKIES — включите значение 1 при публикации через HTTPS.
SMENA_HOST — адрес прослушивания; по умолчанию 127.0.0.1.
SMENA_PORT — порт; по умолчанию 8000.
SMENA_PROXY_IPS — доверенные IP обратного прокси через запятую; по умолчанию 127.0.0.1.
  Только доверенный прокси может передавать реальную схему HTTPS через X-Forwarded-Proto.
  Для внешнего доступа настройте HTTPS и запретите обход прокси прямым доступом к Uvicorn.
Переменные задаются в оболочке или панели хостинга. Файл .env автоматически не читается.

DOCKER И ПУБЛИКАЦИЯ
Dockerfile содержит Python-сервер, интерфейс и зависимости, запускает приложение не от root.
Сборка: docker build -t smena-fastapi .
Перед запуском задайте SMENA_JWT_SECRET и SMENA_SETUP_TOKEN в окружении.
Пример генерации в PowerShell (значения остаются в окружении этого окна):
$env:SMENA_JWT_SECRET = & .\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(48))"
$env:SMENA_SETUP_TOKEN = & .\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(32))"
Сохраните JWT-секрет в защищённой настройке хостинга и используйте тот же при перезапуске.
Пример команды для проверки на своём компьютере (одна строка):
docker run --rm -p 127.0.0.1:8000:8000 -v smena-data:/app/data -e SMENA_JWT_SECRET -e SMENA_SETUP_TOKEN smena-fastapi
Для размещения в интернете нужен хостинг Python/ASGI или сервер с Docker, HTTPS и постоянным диском.
База и локальный ключ находятся в /app/data; подключите постоянный том и резервное копирование.
SQLite-версия предназначена для одного экземпляра приложения с общим локальным файлом базы.
Dockerfile подготовлен для развёртывания; наличие Dockerfile само по себе не означает публикацию.

Текущий адрес https://smena-worktime-adilk.adilium.chatgpt.site продолжает использовать
прежний JavaScript-сервер Cloudflare Workers и свою D1-базу. Среда Sites не запускает
обычный Python-процесс Uvicorn. Локальная версия FastAPI доступна по адресу localhost:8000.
Публичная версия на Python требует отдельного развёртывания и переноса облачных данных.
Файлы прежней серверной оболочки сохранены для обслуживания опубликованного сайта.

ОФОРМЛЕНИЕ
Шрифт загружается с самого сайта, внешние сервисы для оформления не нужны.
Эффекты указателя работают только с мышью; на сенсорном экране фон остаётся статичным.
Системная настройка уменьшения движения отключает декоративные анимации.
Оформление не изменяет сохранённое рабочее время и права доступа.

СТАРЫЕ ДАННЫЕ
Новая версия не удаляет старый ключ smena.state.v1 из localStorage.
Эта история остаётся в том браузере и адресе, где была создана; в SQL автоматически не переносится.
В новой базе нет вымышленных сотрудников и заранее заданного пароля администратора.
